# Fuzzing the ITCH path

`itch_fuzz.cpp` defines one libFuzzer entry point, `LLVMFuzzerTestOneInput`, with three
targets. The first input byte selects one (modulo 3):

* **0**: `replay()` of the rest as a length-prefixed ITCH file, lenient and strict. Checks
  book invariants, frame accounting (`decoded + decode errors == frames`), that strict mode
  never processes more frames than lenient mode, and determinism (two replays, same hash).
* **1**: the rest is a sequence of 2-byte-length-prefixed MoldUDP64 packets. They are fed
  to a `Sequencer` with small bounds (256 messages, 4 KiB), and each delivered message is
  ITCH-decoded and applied to a book. Checks strictly in-order, exactly-once delivery and book
  invariants. After every packet it also checks that `missing()` is sorted, disjoint,
  non-adjacent and inside `[next_expected, horizon)`, and that holes plus buffered messages
  fill that range exactly.
* **2**: `parse_request()` round trip (and that no valid 20-byte request is rejected), then a
  `PacketStore` built from the rest: every packet parses back to the same messages within the
  MTU, and `find()` agrees with every packet's range.

A violated check calls `abort()`, so any fuzzer or sanitizer reports it as a crash.

## Coverage-guided (libFuzzer: Linux clang)

```bash
cmake -S . -B build/fuzz -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_CXX_COMPILER=clang++ \
      -DENGINEX_SANITIZER=address,undefined -DENGINEX_FUZZ_LIBFUZZER=ON
cmake --build build/fuzz --target enginex_fuzz_itch
mkdir -p /tmp/itch-corpus && cp tests/testdata/itch/*.itch fuzz/corpus/* /tmp/itch-corpus/
./build/fuzz/enginex_fuzz_itch /tmp/itch-corpus -max_total_time=600
```

The `/tmp/itch-corpus` copy keeps libFuzzer from writing new inputs into the repository.
Apple clang ships no libFuzzer runtime, so this build has **not** been run in the development
environment. It is provided for Linux.

## Standalone (any compiler; what has actually been run)

`standalone_driver.cpp` calls the same entry point from a seeded mutation loop over the
corpus: bit flips, byte sets, inserts, deletes, truncations, and splices from other corpus
files. It is reproducible from its seed but **not coverage-guided**.

```bash
./build/release/enginex_fuzz_itch_standalone 1000000 42 \
    tests/testdata/itch/lifecycle.itch tests/testdata/itch/malformed.itch \
    fuzz/corpus/mold_packets.bin fuzz/corpus/mold_gaps.bin
```

ctest runs 20 000 inputs (`fuzz_itch_standalone_smoke`). Longer runs and their results are
recorded in `docs/itch.md § Verification`.

`fuzz/corpus/mold_packets.bin` and `mold_gaps.bin` are generated by `tools/itch_fixture.py`.
The first is the lifecycle fixture as in-order MoldUDP64 packets. The second holds the same
messages out of order, with a heartbeat that reveals a hole, adjacent holes, fills in the
middle of holes, overlapping retransmissions and an end of session. Without that second
seed, 200 000 inputs did not catch a sequencer that fails to merge adjacent holes. With it,
the hole-range check catches that mutant. `--check` keeps both files in sync.
