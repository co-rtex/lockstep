# Fuzzing the ITCH path

`itch_fuzz.cpp` defines one libFuzzer entry point, `LLVMFuzzerTestOneInput`, with two targets.
The first input byte selects one:

* **even**: `replay()` of the rest as a length-prefixed ITCH file, lenient and strict. Checks
  book invariants, frame accounting (`decoded + decode errors == frames`), that strict mode
  never processes more frames than lenient mode, and determinism (two replays, same hash).
* **odd**: the rest is a sequence of 2-byte-length-prefixed MoldUDP64 packets. They are fed
  to a `Sequencer` with small bounds, and each delivered message is ITCH-decoded and applied
  to a book. Checks strictly in-order, exactly-once delivery and book invariants.

A violated check calls `abort()`, so any fuzzer or sanitizer reports it as a crash.

## Coverage-guided (libFuzzer: Linux clang)

```bash
cmake -S . -B build/fuzz -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_CXX_COMPILER=clang++ \
      -DENGINEX_SANITIZER=address,undefined -DENGINEX_FUZZ_LIBFUZZER=ON
cmake --build build/fuzz --target enginex_fuzz_itch
mkdir -p /tmp/itch-corpus && cp tests/testdata/itch/*.itch fuzz/corpus/* /tmp/itch-corpus/
./build/fuzz/enginex_fuzz_itch /tmp/itch-corpus -max_total_time=600
```

The `/tmp/itch-corpus` copy keeps libFuzzer from writing new inputs into the repository.
Apple clang ships no libFuzzer runtime, so this build has **not** been run in the development
environment. It is provided for Linux.

## Standalone (any compiler; what has actually been run)

`standalone_driver.cpp` calls the same entry point from a seeded mutation loop over the
corpus: bit flips, byte sets, inserts, deletes, truncations, and splices from other corpus
files. It is reproducible from its seed but **not coverage-guided**.

```bash
./build/release/enginex_fuzz_itch_standalone 1000000 42 \
    tests/testdata/itch/lifecycle.itch tests/testdata/itch/malformed.itch fuzz/corpus/mold_packets.bin
```

ctest runs 20 000 inputs (`fuzz_itch_standalone_smoke`). Longer runs and their results are
recorded in `docs/itch.md § Verification`.

`fuzz/corpus/mold_packets.bin` is generated by `tools/itch_fixture.py`: the lifecycle fixture
as MoldUDP64 packets. `--check` keeps it in sync.
